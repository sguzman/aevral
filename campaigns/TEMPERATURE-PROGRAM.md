# Fixed-data temperature research program (C003–C015)

Authorized 2026-11-26. Goal: extensive comparative research over major practical forecasting families for KSEA next-24-hour temperature, not a claim to enumerate every possible algorithm. Completed C001/C002 remain immutable. Incumbent: 80→64→24 MLP, SGD .005, 30 epochs, seed42, 2026 historical MAE 1.35264044°C. This is not a threshold on new folds.

## Scope and two tracks
- Fixed data: already fingerprinted 2000–2025 annual files and January–October 2026 partial file in results/AEV-015/snapshot.sha256. No additional observations, stations, external weather models, pretrained weights or domains. Raw data in CI cache; cache eviction or upstream drift is a blocker, not permission to replace hashes. Rust-first, GitHub-hosted CI, no local downloads; pinned dependencies allowed when justified, use Nix where practical. Do not implement a misleading approximation just to claim coverage.
- Track A (primary): original 80 inputs, identical matched origins and 24 hourly Celsius targets. Same information at forecast origin; fitted history parameters are allowed, but extra per-origin history belongs to B. Models requiring unavailable future covariates must adapt causally or be marked inapplicable.
- Track B (secondary, C011 onward): alternative causal representations and longer histories from those same frozen files only. Compare on intersection with A and separately report natural coverage; never silently compare different cohorts. No gap interpolation using future values.

## Evaluation contract (C003 implementation gate)
1. Reproduce C002 incumbent seed42 2019–2022 validation MAE 1.35014439 and baseline/cohort (121849 train, 30207 validation). Confirm 27 hashes and train-only transforms; original split semantics remain unchanged. Expose reusable rows/forecast API without reading beyond required origin. Preserve original scores.
2. Development tournament rolling-origin annual validation folds: expanding training ending 2018, 2019, 2020, 2021 respectively; validate calendar years 2019, 2020, 2021, 2022. Require full 24 target hours within assigned interval; train labels strictly prior; use causal prior history across boundaries. Fit preprocessing, hyperparameters, calibration only on allowed training/development partitions; no target leakage from overlapping windows. Use same fixed origin set for every candidate per fold; report coverage and failures. For expensive screens use 2019 fold or deterministic predeclared train-only budget/subsample, not test data; finalists all four full folds. Refit incumbent per fold under frozen recipe. Use pooled matched-origin MAE in °C as primary selection; RMSE, per-lead and per-season MAE, cost, memory and parameter count where meaningful. Tie-break by RMSE then compute cost. Record fold-specific means and seed variability; no naive iid significance.
3. Historical 2023–2025 and Jan–Oct 2026 scores already exposed by C001/C002. No fresh holdout can honestly be manufactured from existing data. Reserve these from new hyperparameter/ensemble selection; in C015 freeze candidate shortlist/configs, then evaluate expanding chronological retrospective folds (2023, 2024, 2025, Jan–Oct 2026) using past-only fitting and fixed recipes. Report as retrospective/exposed-period backtest, NOT independent confirmation. Also include a fixed-original-train comparison to C002 on 2026 for finalists if affordable, clearly labeled exposed. No tune/retry after final ranking except documented implementation failures with same config. If user later approves, prospective data can confirm a new frozen winner; not part of completion.
4. C003 must publish a versioned experiment registry and manifest with fold counts, data hashes, seeds, train/eval IDs, fit/score separation, per-origin prediction schema (origin, lead, target, prediction, model, fold), metric parity tests, and reproducibility instructions. Keep bulky per-origin data as CI artifacts (record retention limitations); preserve aggregated records, configurations and manifests in Git. Avoid presenting synthetic checks as measured results.

## Finite campaign budget and gates
- C003 harness first. Each remaining model campaign begins by committing an explicit finite candidate/config manifest with required representatives for each listed family. Families are complete only when measured or explicitly justified blocked/inapplicable; never equate failed runs with results. Start with at least one faithful representative per applicable named family; closely related methods may share backends. For costly variants, document mathematical and computational constraints and use an appropriate approximate representative where feasible.
- Screening budget: up to 12 configurations per named method, one development fold; maximum 96 screening configs per campaign per manifest (split into sub-batches, prioritize family coverage; multiple variants within a family are optional after required coverage). Promote top two configurations per distinct family and incumbent to full four-fold evaluation; for stochastic finalists use seeds 42,123,2026. Deterministic methods one run. Publish negative results, wall times, peak memory, runner type, and failures. Default each CI job <= 30 min, <= 6 parallel, max 2 GB model workspace target (report deviations), split slow runs; preflight expensive algorithms; retry infrastructure errors once, fix code defects without changing scientific recipe. No paid compute without explicit approval. CI quotas/availability may block. No endless parameter search.
- C012 dedicated optimizer budget: up to 128 predeclared trials per campaign across a shortlist of up to eight representative models; use development-fold successive halving, compare on all folds after selection. C013 combinations max 48; C014 distributional trials max 48; C015 shortlist max 12 single models plus 4 ensembles, all frozen before retrospective assessment. Budget increases require approval. Report actual counts, not plans as results.
- Acceptance: common harness verified, every campaign manifest resolved, all evaluated candidates ranked, negative/failure records included, final retrospective tournament completed and report+STATE persisted. No requirement to beat incumbent. Stop at budget/acceptance, no automatic cross-domain work. No human QA required unless a genuine blocker or decision outside approved scope.
