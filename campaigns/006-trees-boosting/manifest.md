## Implementation contracts
- T01 exact numeric greedy split: sort node values for candidate features, test valid boundaries between distinct values, minimize summed squared error over all output coordinates (scalar in per-lead), deterministic tie-breaking; leaf vector means, min leaf enforced, constant target handling. Multi-output means shared partition, not 24 independent trees. 
- T02 bootstrap independent shared-output CART; T03 bootstrap and sample feature subset without replacement at each node; T04 random candidate thresholds uniform in observed feature range with no bootstrap, retain best legal random split, not renamed random forest. Use reproducible RNG and report actual tree/node/leaf counts. All ensemble point outputs averaged.
- T05 train-only quantile/bin thresholds, gradient residuals for squared loss, greedy binned multi-output SSE splits, stagewise residual fit and shrinkage, initial train target mean; not a branded boosting library. T09 true pinball-loss boosting: median initialization, negative pinball subgradient split pseudo-responses, per-lead median residual leaf update (not average of signs), shrinkage; report train objective and no claim of exact global optimization.
- T06–T08 require actual upstream XGBoost, LightGBM and CatBoost executable/library backends. Prefer official CPU CLI tools exposed through the existing pinned nixpkgs rev 0dc498bfe49baeb18b0f9891e800b53bb2603193; verify availability and exact version in hosted CI. If absent, use a separately pinned upstream release/source and checksum-verified reproducible Nix derivation only if feasible under the existing CI budget. Freeze versions, executable interface, objective, deterministic options, threads and dependency lock before fits; no Python runtime or unpinned downloads required by user, no imitation under branded name. Rust exports train/eval feature rows and labels and imports predictions with exact ordered origin/lead schema, train and eval kept separate, labels never supplied to prediction command where avoidable, no early stopping on evaluation fold. If official backend unavailable or cannot be pinned within budget, record explicit blocked outcome. No paid compute or local downloads.
- Resource limits: <=6 concurrent CI jobs, <=30 min/job, <=2 GB model workspace target, use <=2 threads/backend; preflight exact split and per-lead workloads and guard at 1200s elapsed fit budget. Group/split jobs as appropriate, no change to model recipe after scoring. If forecast cannot complete in budget, explicit resource-blocked outcome; infrastructure retry once; implementation defect correction same recipe. Before each batch commit exact split/gain equations, binning and seed policy, tests, resource guard and workflow. Record fit and score seconds, RSS, actual tree/leaf counts and scalar parameter count convention, lead/month metrics, code/backend/seed, negatives and blocks. Tests include known split, shared-vs-scalar, constant target, min leaf, random reproducibility, no future targets and pinball leaf median where applicable. No new data.
